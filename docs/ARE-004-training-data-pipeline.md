# ARE-004 — Training Data Ingestion & Cleaning

## Назначение и запуск

Pipeline загружает выбранные полные истории пользователей из официального
Hugging Face, проверяет схему, очищает взаимодействия и формирует локальный Parquet.
Не обучает модели, не строит split и не превращает рейтинги в implicit feedback.
YummyAnime API и история собственного профиля в этом pipeline не используются.

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev,data]"
# Первый запуск: только после согласования полного прохода источника.
.venv\Scripts\python.exe -m anime_recommender.ingestion.pipeline --allow-full-scan
# Последующие запуски: кэш, без сетевых запросов.
.venv\Scripts\python.exe -m anime_recommender.ingestion.pipeline
```

Конфигурация: `configs/training_data.json`; другой файл задаётся через `--config`.
Относительные пути разрешаются от корня проекта, пути данных ограничены `data/`.
Настраиваются immutable source revision, SHA-256/размеры, sample_users, seed,
размер чанка, cache/output paths, границы оценок и conflict_policy.
Минимальные зависимости `data`: pandas, requests, pyarrow. Jupyter не требуется.

## Полнота историй и объём сети

У источника нет проверенного пользовательского индекса. Без полного чтения нельзя
гарантировать полные истории: начало/конец произвольного byte range не являются
границами истории. Пользователь явно разрешил один полный потоковый проход
ratings.csv (~2,25 GB трафика), сохраняя только выборку. Отдельного большого CSV
на диске не создаётся. Нет автоматических повторных попыток при сбое.

По умолчанию — 1000 пользователей, seed=42, чанки по 250000 строк. Пользователи
выбираются по 1000 наименьшим приоритетам SHA-256(seed:userID), с ID как tie-breaker.
Heap хранит текущий порог; он может только уменьшаться. Если пользователь входит
в итоговую выборку, он был принят при первом появлении и не был исключён позже.
Поэтому сохраняются все его строки независимо от порядка исходника и границ чанков.
Проверено на перемешанном синтетическом источнике и различных размерах чанков.

Это не «первые 1000 пользователей» и не произвольные N строк. Размер результата
в строках зависит от активности выбранных пользователей. Истории полные относительно
зафиксированного исходного снимка, а не всей истории человека на исходных сайтах.

До признания выборки полной сверяются размер и SHA-256 всего прочитанного CSV.
Кэш имеет manifest с revision, алгоритмом, seed, размером выборки, количеством
просканированных строк и контрольными суммами. Рейтинг source хранится как string,
что позволяет сохранить исходное представление до очистки.
Повторный запуск проверяет manifest и файлы, не вызывает сеть. Несовпадение
параметров или повреждение кэша вызывает ошибку, а не незаметную загрузку заново.
Для другой выборки выбирайте новый cache_dir в конфигурации и согласуйте новый scan.

## Проверки и очистка

Критические ошибки: отсутствующие обязательные колонки, нецелые/неположительные
или отсутствующие IDs, переполнение int64, повтор первичного ключа каталога,
пустое название, несовпадение source/cache checksum и некорректная конфигурация.
Они останавливают pipeline с пояснением. Quality report имеет status=success
для завершённого запуска или status=failed и причину при отказе. При некорректном
пути конфигурации или недоступности диска отчёт записать нельзя: причина остаётся
в сообщении CLI. Failed-отчёт не подтверждает качество оставшихся старых таблиц.

Для взаимодействий порядок очистки фиксирован; счётчики удалений не пересекаются:

1. Пропуски оценок и недопустимые/нечисловые/бесконечные оценки удаляются раздельно.
2. Удаляются точные повторения userID, animeID, исходного представления rating.
3. Если после этого у пары больше одной численно различной оценки, удаляется вся
   оставшаяся конфликтующая пара. Без timestamps не выбирается «последняя» оценка.
4. Эквивалентные текстовые варианты одной оценки (`8`/`8.0`) оставляют одну строку;
   это отдельная причина удаления, а не конфликт оценок.
5. Исключаются взаимодействия без безопасного mapping к MAL.

Для каждого запуска выполняется баланс: input_rows = output_rows + сумма удалений.
Показатели очистки относятся к выбранным полным историям, а не к аудиту рейтингов
всех 148 млн строк. При сканировании всего источника проверяются обязательные
колонки и идентификаторы, необходимые для корректного отбора пользователей.
Нули допустимы в границах [0,10] по фактически найденным данным ARE-003 и сохраняются.
Рейтинги не масштабируются, не округляются и не бинаризуются. В `rating_raw`
сохраняется исходное текстовое значение выбранной строки, в `rating` — число float64.

## Каталог и mapping

Обязательные поля: animeID, title, mal_url. Внутренний animeID не является MAL ID.
MAL ID извлекается только из http(s) URL myanimelist.net/anime/{positive integer}.
Варианты с www, названием после ID и query/fragment допускаются.
Отсутствующие/некорректные MAL URL и ВСЕ строки с неоднозначным MAL ID изолируются
в catalog_quarantine.parquet с причиной. Сначала выбрать одну из неоднозначных
строк и только потом убрать дубликаты недопустимо.

Основной каталог и mapping содержат только безопасные однозначные соответствия.
Остальные исходные метаданные каталога сохраняются. Исходный CSV остаётся в кэше.
Удалённые взаимодействия отражаются в счётчиках; их исходные строки остаются
в локальном кэше выборки, поэтому очистку можно пересмотреть без повторной сети.

## Локальные результаты

```text
data/
  raw/training_sample/
    anime_catalog.csv
    sample_interactions.parquet
    manifest.json
  processed/
    clean_interactions.parquet
    anime_catalog.parquet
    anime_id_mapping.parquet
    catalog_quarantine.parquet
    data_quality_report.json
```

`clean_interactions`: dataset_user_id:int64, dataset_anime_id:int64,
rating:float64, rating_raw:string, myanimelist_id:Int64.
`anime_id_mapping`: dataset_anime_id → myanimelist_id, оба ключа уникальны.
`anime_catalog`: dataset_anime_id, myanimelist_id и исходные метаданные.
Пустая quarantine — нормальный результат, если mapping полностью корректен.

Каждый файл заменяется атомарно через временный файл. Quality report записывается
последним, содержит параметры, provenance, причины удаления, версии Python/библиотек
и hashes результатов. Повторяемость байтовых hashes проверяется в одном окружении;
при смене версии Parquet writer сравнивайте также логические таблицы.
Группа файлов не является транзакцией: при аварии следует повторить запуск и
проверить hashes из завершённого отчёта. Одновременные запуски в один каталог
не поддерживаются. Локальный кэш не является MLflow/model registry.

Все данные, кэш, временные результаты и отчёты в data/ исключены из Git.
В репозиторий входят только код, конфигурация, синтетические тесты и документация.
При исчерпании памяти/диска или прерывании сети нет автоматического retry/resume:
новый полный scan требует отдельного явного запуска. Изменение объёма sample_users
может изменить потребление RAM; весь source в память не помещается.

## Проверки

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m pip check
```

Тесты используют маленькие синтетические данные и fake HTTP response. Они проверяют
схему, повреждения, IDs, MAL URL, неоднозначный mapping, дубликаты, конфликтующие
оценки, сохранение нулей, полноту историй при перемешивании, воспроизводимость,
запрет неразрешённого full scan и повторный запуск без сети.

Лицензия и происхождение исходного набора: см.
[ARE-003](ARE-003-training-dataset-research.md). Источник:
https://huggingface.co/datasets/mramazan/User-Animelist-Dataset

выборки можно повторять и менять без сети.
