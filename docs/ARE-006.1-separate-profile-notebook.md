# ARE-006.1 — Separate YummyAnime recommendations notebook

Notebook 04 retains model configuration/training, validation context/target,
fold-in diagnostics and comparison plots. It has no nickname parameter, profile
inference calls or API requests. Notebook 05 is dedicated to a single public
YummyAnime profile and never trains models or loads interaction splits.

## Files

- `notebooks/04_recommendation_models.ipynb`: remove the profile experiment.
- `notebooks/05_yummyanime_recommendations.ipynb`: input, saved-model loading,
  profile inference, coverage, recommendation table and optional history display.
- `recommendation_exploration.py`: saved-model/catalog-only loader, presentation
  summary/table and reranking a fetched profile without new HTTP requests.
- `tests/test_recommendation_exploration.py`: nickname precedence, missing models,
  profile switching, K changes, error handling and notebook structure checks.
- README and this report document the new workflow.

Existing HTTP, normalization, binary feedback, MAL mapping, fixed-item fold-in,
seen exclusion and fallback logic are reused. The ranking/fallback branch is shared
by initial profile inference and subsequent reranking. No new weights, model changes,
training data changes or services. Local edits to Notebook 01 were left untouched.

## Usage

Open Notebook 05 with the existing `.venv` kernel. Configure the public application
token in local `.env`. Run cells from top to bottom:

1. `YUMMYANIME_TEST_NICKNAME` takes precedence; otherwise enter a nickname.
   Empty input selects `First_Light`. Inputs remain only in memory.
2. Load the saved ARE-006 models and certified catalog. If missing, the error points
   to `python -m anime_recommender.training.pipeline`, to run separately after
   preparing ARE-005.1 data. Notebook 05 has no training path.
3. Fetch the profile, lists and favorites using three bounded public-token requests.
   Ratings and MAL IDs are already in list records; no stats request is necessary.
4. Inspect counts, catalog/train coverage and Top-N (Rank, English Title, Russian
   Title, ALS Score, MAL ID). Default K is 15, configurable in the parameter cell.
5. Change only `top_k` and rerun Top-N to reuse the fetched history without new requests.
   Change nickname and rerun profile fetching to load that profile.
6. Set `show_history=True` and rerun the history cell for optional private inspection.

Positives remain binary: rating>=5, completed with zero/missing rating, or favorite;
planned/dropped veto positivity. Watching alone is not positive. Only warm positives
are passed to ALS. Every mapped known item is excluded. Popularity is used only when
a successfully fetched profile has no warm positives, never after an API failure.

## Limitations and privacy

YummyAnime links are omitted because the local training catalog lacks a certified
YummyAnime ID/URL mapping for recommended titles. MAL IDs are not YummyAnime IDs.
Unknown MAL IDs cannot be used to identify catalog items. Live snapshot counts can
change. Scores are ranking dot products, not probabilities. This remains an
experimental profile adapter, with no inference-quality claims or ARE-007 work.

Notebook outputs must be cleared before saving; Jupyter may autosave personal data
during interactive use. No API responses, lists or entered nicknames are written by
the helpers. Both notebooks are delivered with empty outputs/execution counts.
No commit or push is authorized for this task.

## Follow-up: Top-15 and source-backed titles

The local catalog contains `title` and `alternative_title`, but no Russian-title
field. The primary title is used for the English column when no explicit English
field exists; some primary titles can be romanized names rather than licensed
English titles. `alternative_title` is not treated as Russian.

The [official Swagger documentation](https://ru.yummyani.me/api/swagger) documents
`GET /anime` with a `mal_ids` array filter, `limit` and `offset`, plus a primary
`title` and `remote_ids.myanimelist_id` in each result. A single-item real probe
(MAL 2167) returned HTTP 200 and the source catalog title «Кланнад». This is a
YummyAnime catalog label, not a claim of a rights-holder-approved translation.

New `inference/recommendation_table.py` forms the five display columns without
changing IDs, ranks, scores, factors or filtering. Explicit local English/Russian
fields take precedence when present. The existing client adds a single bounded
metadata request for at most 20 selected MAL IDs. No pagination, per-item loop of
requests, bulk catalog collection or automatic retries are added. Exact MAL
matches with a single catalog entry and a Cyrillic primary source title may fill
the Russian column; unknown-language aliases are not used. Metadata is cached only
in the in-memory profile result. Repeating the same K adds no metadata requests;
newly selected IDs may require one further bounded lookup. For K>20, missing titles
beyond the request cap remain unavailable in that rendering.

Missing titles, unmatched MAL IDs, ambiguous multiple entries, non-Russian primary
titles or metadata API errors produce `—`, without machine translation. API errors
are displayed separately and do not change the already generated recommendations.
Popularity still uses its existing counts and fallback mechanism; its ALS Score is
shown as `—`, so popularity counts cannot be mistaken for ALS outputs. The selected
model is shown in the profile summary.
