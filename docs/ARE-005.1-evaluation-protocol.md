# ARE-005.1 — Final dataset protocol before the first ALS experiment

Date: 2026-11-12. Replaces the v1 protocol in ARE-005. No model is trained.

## Corrected order

1. Load checksum-verified, local ARE-004 tables. Source ratings and files are unchanged.
2. Allocate all 1000 source users by seeded hash to 800 train / 100 validation /
   100 test. Allocation depends on user IDs only, not scores/items/popularity.
3. Split each validation/test user's RAW cleaned interactions approximately 80/20
   using the existing user-item hash. At this point ratings and train vocabulary
   are not consulted. Very short histories remain; if raw context and target
   minima cannot both fit, retain history in context with empty raw target.
4. Apply rating >=5 independently to train, observed context and hidden target.
   Thresholds 5,6,7,8 remain configurable. Zeros/missing scores are not positives.
   Source ratings/rating_raw remain unchanged; confidence stays uniformly 1.
5. Apply minimum 5 positives per user and 5 users per item ONLY to train, reaching
   a train-only k-core. No automatic threshold relaxation or eval reallocation.
6. Derive item vocabulary only from final train. Retain every eval user in their
   cohort mapping, even with zero positive context, zero warm context or zero
   positive target. Mark OOV positive rows is_cold_item; never silently discard them.

The full eval positive history is used only for diagnostics/exhaustiveness checks,
AFTER raw partitioning. It is never an eligibility criterion. Changing held-out
ratings cannot change raw membership, observed positive context, its CSR, train
vocabulary or retained eval user IDs. Tests verify this directly.

Raw observed context/target are saved separately, so this order can be audited.
`min_user_positives=5` and `min_item_users=5` are TRAIN-only minima. Config fields
`min_context`/`min_target` are raw-history allocation preferences, not positive-count
filters. No positive-count threshold is applied to evaluation users.

## CSR and leakage checks

Train CSR uses only train positives. Validation/test context CSR use ONLY positive
observed context whose dataset_anime_id is in the train item mapping. Their shapes
include every assigned user, including zero rows. Target is not a matrix-builder
argument, and target entries never contribute to user-factor input. No factors
are calculated yet.

Checks cover user-disjoint allocation, complete raw context/target union, no pair
overlap, positives staying on their original raw side, complete positive retention,
all assigned eval users, cold flags, train-only vocabulary, stable mappings, train
and context CSR shapes/coordinates/nnz. No dense user-item matrix is constructed.

## Future evaluation definitions

Full Recall@K: per-user hits divided by ALL positive hidden targets, including
cold items, averaged over users with a nonempty positive target. Cold targets are
misses for ALS-only. An ALS-only user without warm context receives an empty list
and zero Full Recall if targets exist; evaluate a popularity fallback as a separate
end-to-end system. Publish the metric denominator and full assigned cohort size.

Warm Recall@K: diagnostic metric on users with warm context and at least one warm
positive target, with denominator restricted to train-vocabulary targets. Publish
this conditional cohort size, cold shares and excluded/no-target counts; do not
present it as whole-service quality. No Recall metrics are calculated before ALS.
Future model/threshold tuning uses validation only; test is evaluated after the
protocol and parameters are frozen. Never tune train minima from test coverage.

## Architectural decision and limits

[ADR-001](ADR-001-yummyanime-positive-feedback.md) requires future YummyAnime fold-in
to support watched-unrated, positive-rated, favorites and optionally weak watching
signals. Fallback is for absence of usable known-item positives, not absence of scores.
This is documentation only; inference is not implemented.

Final verification: 86 offline tests pass, pip check passes, two repeated real
runs have identical reports/artifact hashes, all tables and three CSR matrices
restore successfully. Notebook 03 executed top-to-bottom with networking forbidden;
all saved notebooks have empty outputs. Source ARE-004 hashes remain unchanged.
Production src imports no Jupyter/Notebook dependencies. No ALS training occurred.

The corrected protocol removes the prior full-positive-count eligibility bias.
It still has retrospective snapshot/exposure and source-user sampling biases.
Without timestamps, random raw holdout is not future-viewing prediction.
The 1000-user sample is for development; different thresholds change labels and
train vocabulary but not raw eval membership for fixed source IDs/items and seed.
