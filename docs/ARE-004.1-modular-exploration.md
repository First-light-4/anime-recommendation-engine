# ARE-004.1 — Modular API and training-data exploration

## Responsibilities

- `ingestion/yummyanime.py`: `YummyAnimeClient`, four read-only endpoints, sanitized
  HTTP/network/authentication errors and a log containing endpoint templates only.
  Explicit public application token, no Bearer, redirects, retries or Jupyter dependency.
- `preprocessing/user_data.py`: API list objects to a stable eight-column DataFrame;
  safe nested access, numeric types and watch-status distribution. Raw input remains
  unchanged; no deduplication, zero imputation or fabricated favorite watch status.
- `evaluation/user_data.py`: missing values, duplicates, coercions, rating summary,
  favorite-membership checks, profile rating-distribution checks and manual UI counts.
- `ingestion/processed_data.py`: read existing ARE-004 tables, verify successful quality
  report and file hashes. Missing/corrupt data causes an error, never a download.
  Reuses ARE-004 checksum and schema helpers; does not repeat cleaning.
- `evaluation/training_data.py`: descriptive statistics, sparse-pair density and
  MAL-based matching to the full catalog versus the active interaction vocabulary.
  Ambiguous mappings are rejected rather than arbitrarily selected.
- `exploration.py`: research orchestration with an explicit client and typed result.
  Stops after the first API error. No global notebook variables or response persistence.
  A partially loaded frame is never reported as a complete API check.


Select the local `.venv` kernel. `01_yummyanime_api_exploration.ipynb` uses the public
token in local `.env` and the nickname parameter. It makes at most four requests.
`02_training_data_exploration.ipynb` loads only `data/processed/`; with
`check_profile=True` it makes two read-only profile requests. Set False for fully
offline training exploration. No source Hugging Face download or ingestion is run.

The notebooks contain imports, parameters, module calls and display/describe/head.
No HTTP implementation, exception handling, normalization, ID-matching algorithm
or metric implementation remains in their cells. Configuration loading is explicit
via python-dotenv; the reusable HTTP client itself never reads `.env`.

## Public function example

```python
from anime_recommender.ingestion.yummyanime import YummyAnimeClient
from anime_recommender.preprocessing.user_data import normalize_user_lists
from anime_recommender.evaluation.user_data import user_quality_report
from anime_recommender.ingestion.processed_data import load_processed_data
from anime_recommender.evaluation.training_data import map_user_to_training

# Supply the public token from your application's configuration, never a literal.
client = YummyAnimeClient(application_token)
profile = client.get_user(nickname)
rows = client.get_lists(profile["id"])
frame = normalize_user_lists(rows)
quality = user_quality_report(rows, frame)
data = load_processed_data("data/processed")
matched, coverage = map_user_to_training(frame, data.mapping, data.interactions)
```

For a research session, `explore_profile(client, nickname)` fetches the profile,
lists, favorites and rating statistics and stops after the first API error. It
returns a result object with `complete`, sanitized `error`, frame and cross-checks.
The low-level client raises `YummyAnimeError` subclasses for callers to handle.

## Semantics and malformed data

Watch IDs remain 0/1/2/3/5. Favorites filter 4 is not a watch category. `null` remains
missing, unknown integers remain `Other (ID)`. Rating zero remains numeric zero;
only positive `user.rating` is used for the provisional rated-count statistic.
Global anime `rating` is never substituted. No implicit-feedback conversion occurs.

Unlike the old notebook's potentially failing integer casts, malformed/fractional/
boolean integer fields become NA with a coercion counter. This is an explicit
error-handling improvement; valid snapshot semantics are unchanged. Missing and
invalid values remain visible in quality checks, and raw objects are not modified.
Duplicate list rows are reported and retained. Matching uses unique positive MAL
IDs for coverage, while the returned joined frame retains all user records.

## Privacy and limits

Saved notebook outputs and execution counts must remain empty. Live display calls
show personal data in the current session, and Jupyter can autosave it: clear all
outputs before saving or sharing. Restore manual website counters to None.
No response bodies, tokens or private history are written by these modules.
User-profile result repr is suppressed to avoid accidentally dumping its contents.

API availability and a valid public token are prerequisites for live profile cells.
Counter comparison with the website remains manual. Matching rating distributions
supports ownership but does not prove each item rating or that zero means unrated.
One profile does not establish audience-wide coverage. Local artifact verification
detects stale/corrupt files but does not add new source-data validation or training.
No ALS, split, PostgreSQL, FastAPI or external service is implemented.
